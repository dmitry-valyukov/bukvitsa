# Author.today — интеграция для читалки. Состояние проекта

Последнее обновление: 22.08.2026
Автор задачи: Dmitry. Проект в Claude: «author.today link».
Цель: читалка (приложение Bukvitsa), которой нужно подключаться к author.today,
получать список КУПЛЕННЫХ пользователем книг и скачивать их в fb2.

Эта папка (`M:\Bukvitsa\Author.today`) — хранилище знаний и программного кода
по интеграции. Скачанные книги СЮДА НЕ складываются: куда сохранять fb2 — это
дело самого приложения-читалки.

---

## ГЛАВНОЕ РЕШЕНИЕ (принято)

Скачиваем книги через **родную кнопку «Скачать»** на сайте (сайт сам отдаёт
готовый незашифрованный fb2 владельцу книги).

**НЕ идём** путём открытых библиотек (author_today.py, Elib2Ebook, greasyfork-скрипт).
Они тянут тексты глав через API `/v1/work/{id}/chapter/many-texts` или `/reader/{id}/chapter`,
получают их **зашифрованными (AES)** и **сами расшифровывают** зашитой в мобильном
приложении схемой, после чего пересобирают fb2. Это обход технической меры защиты
контента (даже для легально купленной книги) — юридически/этически проблемно и хрупко.

Наш путь дешифровку НЕ использует вообще: мы скачиваем уже готовый файл, который
площадка легально отдаёт через браузер. Это чистый и устойчивый вариант.

## АРХИТЕКТУРА (согласована)

Веб-вью держать постоянно НЕ нужно. WebView нужен максимум для одного шага —
логина, если появится капча/anti-bot. После логина cookie/token отдаём обычному
HTTP-клиенту, дальше всё качается без WebView.

Рекомендованный поток:

1. **Логин → токен**
   `POST https://api.author.today/v1/account/login-by-password`
   body JSON: `{ "login": "...", "password": "..." }` → возвращает `token` (Bearer).

2. **Токен → cookie-сессия** (файл качается с домена author.today, не api., поэтому нужны cookie)
   `GET https://author.today/account/login-cookie-by-token?token=<token>`
   Держим общий cookie-jar. (Альтернатива: логин веб-формой сразу за cookie.)

3. **Список купленных книг**
   `GET https://api.author.today/v1/account/user-library` (заголовок `Authorization: Bearer <token>`)
   → работы пользователя с id и признаком владения. Фильтруем купленные.
   Метаданные/название: `GET /v1/work/{id}/details` или `/v1/work/{id}/meta-info`.

4. **Скачивание fb2** (подход «парсим страницу», НЕ хардкодим эндпоинт)
   `GET https://author.today/work/{id}` с cookie → в HTML найти блок «Скачать»
   и его ссылки (Fb2, Epub, Mobi, «Fb2 без картинок») → GET по нужному href →
   сохранить байты как .fb2. Плюс: URL берём из разметки, переживём смену URL-схемы на АТ.

## ТЕХНИЧЕСКИЕ ДЕТАЛИ API (из реверса открытых проектов)

- Базовый API: `https://api.author.today`  ·  веб-домен: `https://author.today`
- Авторизация: `Authorization: Bearer <token>`; до логина — `Bearer guest`.
- Обновление токена: `POST /v1/account/refresh-token`.
- Текущий пользователь: `GET /v1/account/current-user` (даёт `id`).
- Поиск: `GET /v1/catalog/search` · Главная: `GET /v1/home/home-page`.

Мобильные клиенты представляются спец-заголовками (сервер по ним отличает «своё»
приложение). Пример Android:
```
User-Agent: okhttp/4.12.0 X_AT_API
X-AT-Client: android_1.8.013-GMS
X-AT-Certificate: <SHA1 hex, upper, от секрета приложения>
Accept-Language: ru
```
(в открытых проектах секрет: `rmy8LDkVZR+pSXopxUte7hFbA6I=`).
Для нашего пути со скачиванием файла с веб-домена, вероятно, хватит браузерных
заголовков (реальный User-Agent, Accept, Referer на страницу книги) + cookie.

Про шифрование глав (нам НЕ нужно, справочно): поле `text` главы = base64(AES).
Ключ = MD5( reverse(key) : userId|"Guest" : "FjPg]{2+$8JRvv~(" : certHash ),
первые 16 байт hex используются и как AES-ключ, и как IV. Либо через заголовок
ответа `reader-secret`. Это ровно та защита, которую мы обходим стороной.

## ВАЖНЫЕ НЮАНСЫ

- Cookie обязательны для самого файла (web-домен); одного Bearer на author.today может не хватить.
- У логина есть лимит попыток — не долбить, кэшировать токен, обновлять refresh-token.
- Заголовки слать как браузер. Не частить запросами (троттлинг/бан по IP/аккаунту).
- «Fb2 без картинок» — отдельная ссылка (меньший файл, ~221 КБ против ~1,5 МБ).
- Из облачного контейнера домены author.today / api.author.today НЕ пингуются (гео/сеть).
  Проверять/снимать эндпоинты — только со стороны пользователя (его браузер/сеть).

## ОТКРЫТЫЙ ВОПРОС (блокер для готового кода)

Точный `href` кнопки «Скачать → Fb2» ещё НЕ подтверждён. Он рендерится динамически
и виден только в залогиненной сессии для книги, которой владеешь. Нужен ОДИН реальный
URL скачивания, чтобы собрать рабочий прототип. Способы получить:
- пользователь копирует адрес ссылки «Fb2» (ПКМ → копировать адрес ссылки) и присылает;
- либо снять сетевой запрос через Claude in Chrome в его залогиненном Chrome (нужно
  разрешить расширению работать на author.today).
Тестовая книга у пользователя: «Имя нам Легион» (эксклюзив, куплена).
